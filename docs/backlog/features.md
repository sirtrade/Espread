# Большие фичи

> Порядок = приоритет: верхняя задача — самая важная. Формат и процесс — в
> `README.md` этой папки.

## F-11. Контракт выявления грамматических конструкций
- **Приоритет:** P3
- **Проблема/мотивация:** Утверждённый дизайн грамматического трека требует
  отделить грамматический кандидат от лексической карточки, сохранив один
  review-вызов и совместимость со старыми результатами.
- **Что сделать:** Расширить prompt и Zod-контракт review опциональным
  `grammarCandidates` (максимум 5), добавить чистую серверную валидацию
  canonical key, категории, source form/sentence и упражнения. Невалидный
  кандидат должен отбрасываться независимо от лексических items.
- **Критерии приёмки:** sentence/span-пометка может вернуть 0–1 валидный
  кандидат; одиночное слово не создаёт grammar candidate; старый review JSON
  остаётся валиден; нового LLM-вызова нет; schema/domain/integration tests,
  typecheck и test проходят.
- **Детали/ссылки:** `docs/grammar-track-design.md` §3–4, §12;
  `server/src/llm/review.ts`, `server/src/llm/schemas.ts`.

## F-12. Хранение и жизненный цикл грамматических единиц
- **Приоритет:** P3
- **Проблема/мотивация:** Грамматический шаблон нельзя корректно хранить в
  лексическом `bank_items`: у него другой ключ, контент и сигнал SRS.
- **Что сделать:** Добавить Drizzle-миграцией `grammar_items` и
  `users.grammar_active_pool_limit` (default 10, диапазон 0–50), отдельные
  репозитории и чистый домен статусов/SRS. Completion сохраняет только явно
  принятые кандидаты, повторный canonical key добавляет контекст; reset удаляет
  данные транзакционно.
- **Критерии приёмки:** unique `(user_id, canonical_key)`, до 5 контекстов,
  независимые active/queued/learned/ignored и FIFO-пул; чтение не даёт
  grammar SRS-кредит; миграция совместима с существующими строками; lifecycle,
  completion и reset покрыты тестами.
- **Детали/ссылки:** `docs/grammar-track-design.md` §5–6;
  `server/src/db/schema.ts`, `server/src/services/sessionService.ts`.
- **Зависимость:** F-11.

## F-13. Grammar Review и Bank UX
- **Приоритет:** P3
- **Проблема/мотивация:** Пользователь должен осознанно принять объяснённую
  конструкцию и видеть её отдельно от слов.
- **Что сделать:** Добавить в Review отдельную секцию grammar candidates с
  независимым «Сохранить/Пропустить», API для списка/статусов grammar items и
  отдельную вкладку Bank. Все строки — ru/en/es.
- **Критерии приёмки:** кандидат не сохраняется без явного выбора; source form,
  предложение, перевод и объяснение показаны; вкладка фильтрует четыре статуса;
  старый клиент может завершить review без grammar decisions; typecheck/test и
  webapp build проходят.
- **Детали/ссылки:** `docs/grammar-track-design.md` §8, §12;
  `webapp/src/screens/Review.tsx`, `webapp/src/screens/Bank.tsx`.
- **Зависимость:** F-12.

## F-14. Грамматические карточки в Práctica
- **Приоритет:** P3
- **Проблема/мотивация:** Одного объяснения недостаточно: конструкцию нужно
  активно выбирать и воспроизводить с интервальными повторениями.
- **Что сделать:** Добавить grammar MC cloze на ступенях 0–1 и серверно
  проверяемый typed cloze на 2+, смешивание с лексикой, подсказку без кредита,
  мягкий lapse, daily credit, graduation и cross-card anti-leak. Telegram и
  weaving не включать.
- **Критерии приёмки:** answer отсутствует в видимом prompt/переводе; typed
  грейдится по accepted forms на сервере; клиентские ретраи не пишут SRS;
  grammar reading exposure не двигает ступень; доменные и интеграционные тесты,
  typecheck/test/build проходят.
- **Детали/ссылки:** `docs/grammar-track-design.md` §6–8;
  `server/src/domain/practice.ts`, `webapp/src/components/QuizSession.tsx`.
- **Зависимость:** F-13.

## F-15. Журнал ответов грамматического трека
- **Приоритет:** P3
- **Проблема/мотивация:** Лексические и грамматические попытки должны
  анализироваться без фиктивного FK grammar item на `bank_items`.
- **Что сделать:** После T-2 расширить журнал полиморфным discriminator и
  ссылкой на grammar item либо отдельной таблицей по согласованной модели.
  Атомарно писать первую серверную попытку вместе с изменением grammar SRS;
  хранить card type, correct, hint, latency и stage before/after.
- **Критерии приёмки:** lexical и grammar rows имеют валидную ссылочную
  целостность; ровно один target на строку; update+insert атомарны; bot/legacy
  lexical path не ломается; ретраи не журналируются.
- **Детали/ссылки:** `docs/grammar-track-design.md` §10; T-2,
  `server/src/db/repositories/bank.ts`.
- **Зависимость:** T-2, F-14.

## F-16. Эксперимент по вплетению грамматических конструкций
- **Приоритет:** P3 — требует отдельного решения владельца перед реализацией.
- **Проблема/мотивация:** Встреча конструкции в естественном чтении полезна, но
  текущий строковый `termAppearsIn` не может подтвердить синтаксический шаблон,
  а принудительное вплетение рискует ухудшить текст.
- **Что сделать:** Спроектировать opt-in эксперимент: не более одной
  due-конструкции на статью, структурированное подтверждение из финального
  текста и независимый аудит естественности/CEFR-fit. Экспозиция не даёт
  SRS-кредит.
- **Критерии приёмки:** до кода утверждены дизайн и бюджет; контрольная группа
  не получает grammar target; неподтверждённый паттерн не считается встречей;
  качество статьи не ослабляется; стоимость учитывается отдельно.
- **Детали/ссылки:** `docs/grammar-track-design.md` §9–10;
  `server/src/llm/articleGeneration.ts`, `server/src/llm/articleQuality.ts`.
- **Зависимость:** F-12; отдельное утверждение владельца.

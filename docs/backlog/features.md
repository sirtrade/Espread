# Большие фичи

> Порядок = приоритет: верхняя задача — самая важная. Формат и процесс — в
> `README.md` этой папки.

## F-4. Мотивационный слой: стрик, цели, график прогресса
- **Приоритет:** P1
- **Проблема/мотивация:** Ценность приложения раскрывается через недели
  ежедневного использования, но удерживать пользователя нечем: ни стрика, ни
  целей, ни видимого роста — только счётчики-плитки и вечерний дайджест.
  Научно выверенный SRS бесполезен, если приложение перестали открывать.
- **Что сделать (эскиз):**
  1. Стрик: количество подряд идущих локальных дней с хотя бы одним
     «полезным действием» (завершённое чтение или завершённая тренировка).
     Считать по таймзоне пользователя (см. B-2 — общие хелперы). Показывать
     на Home (🔥 N); упоминать в ежедневном сообщении бота («не потеряй
     стрик»).
  2. График прогресса: слова `learned` и прочитанные статьи по неделям
     (данные уже есть: `read_at` статей; для learned — понадобится
     фиксировать дату, см. F-3 `known_since`).
  3. Дневная цель (опционально, согласовать с владельцем): например «1 чтение
     + 1 тренировка в день», прогресс-бар на Home.
- **Критерии приёмки:** Стрик виден на Home, корректно растёт/обнуляется по
  локальным суткам (тесты на границы суток и таймзоны); график отображает
  реальные данные; всё локализовано; реестр функционала дополнен.
- **Детали/ссылки:** `webapp/src/screens/Home.tsx`, `user_stats`,
  `server/src/scheduler/scheduler.ts` (ежедневное сообщение),
  `docs/retention-audit.md` (Ryan & Deci 2000 — автономия/мотивация).

## F-5. Interleaving и защита от утечек между карточками
- **Приоритет:** P2
- **Проблема/мотивация:** Слова одной статьи идут в тренировке сплошным
  блоком (сортировка `nextDueAt ASC`), делят контекст, и prompt одной карточки
  может содержать ответ другой. Blocked practice стабильно проигрывает
  interleaving.
- **Что сделать:** По этапу 7 роадмапа: выборка кандидатов с запасом и
  перемешивание; анти-утечка (prompt/context карточки A не содержит
  answer/lemma карточки B той же выдачи) на сервере и в клиентском
  `buildQuizCards`.
- **Критерии приёмки:** См. этап 7 роадмапа.
- **Детали/ссылки:** `docs/retention-roadmap.md` этап 7,
  `docs/retention-audit.md` §7–8.

## F-6. Ротация контекстов карточки
- **Приоритет:** P2
- **Проблема/мотивация:** Cloze всегда строится из одного и того же
  `firstContext` — пользователь запоминает предложение, а не слово; знание не
  переносится на новые контексты.
- **Что сделать:** По этапу 8 роадмапа: JSON-колонка `contexts` (3–5 записей),
  захват новых контекстов из статей, где слово реально вплетено, случайный
  выбор контекста в card builder'ах.
- **Критерии приёмки:** См. этап 8 роадмапа.
- **Детали/ссылки:** `docs/retention-roadmap.md` этап 8 (зависимость: после
  F-5 — анти-утечка должна учитывать выбранный контекст),
  `docs/retention-audit.md` §7.

## F-7. Качество дистракторов
- **Приоритет:** P2
- **Проблема/мотивация:** Статический fallback из 10 слов быстро выучивается
  как «всегда неправильные» — карточка решается исключением без знания слова.
- **Что сделать:** По этапу 9 роадмапа: LLM-генерация 5–8 семантически
  правдоподобных same-POS дистракторов на этапе enrichment; расширить
  fallback-пул до ~30 слов на POS со случайным семплированием.
- **Критерии приёмки:** См. этап 9 роадмапа.
- **Детали/ссылки:** `docs/retention-roadmap.md` этап 9,
  `docs/retention-audit.md` §9.

## F-8. Адаптация уровня CEFR по плотности пометок
- **Приоритет:** P2
- **Проблема/мотивация:** Уровень выбирается вручную при онбординге и никак
  не корректируется, хотя готовый сигнал понимания уже есть: доля помеченных
  слов на статью. Слишком лёгкие статьи не дают роста, слишком трудные —
  фрустрируют (для инцидентального усвоения нужно ~95–98% покрытия текста).
- **Что сделать (эскиз):** Считать скользящую плотность пометок по последним
  N (например, 5) завершённым чтениям. При стабильно низкой (< ~2%) —
  предлагать повысить уровень, при стабильно высокой (> ~8%) — понизить.
  Только **предложение** (баннер на Home / после завершения чтения с кнопками
  «Повысить до B1» / «Оставить»), не автосмена. Пороги — константами, с
  обоснованием в реестре функционала.
- **Критерии приёмки:** Предложение появляется только при устойчивом сигнале
  и не чаще раза в X дней; решение пользователя запоминается (отказ не
  переспрашивается сразу); тесты на расчёт плотности; всё локализовано.
- **Детали/ссылки:** `articles.marks` (архив пометок), `users.level`,
  `webapp/src/screens/Home.tsx`, `docs/functionality-registry.md` §6.3
  (частотные потолки уровней).

## F-9. Грамматический трек (конструкции, а не только лексика)
- **Приоритет:** P3 — идея, требует обсуждения объёма с владельцем.
- **Проблема/мотивация:** Приложение работает только с лексикой. Помеченное
  предложение сворачивается в карточку из 2–4 слов; систематической работы с
  грамматикой (перифразы, времена, subjuntivo) нет, хотя пометки целых
  предложений — часто именно про грамматику.
- **Что сделать:** Сначала — согласованный с владельцем дизайн-документ:
  что считаем «грамматической единицей», как её выявлять из пометок
  предложений (LLM-разбор уже умеет находить «конструкцию, вероятнее всего
  вызвавшую затруднение»), как тренировать (объяснение? мини-упражнения?
  вплетение конструкции в следующие статьи?). Реализацию не начинать без
  утверждённого дизайна.
- **Критерии приёмки (для первого шага):** Дизайн-документ в `docs/`,
  согласованный владельцем; задачи на реализацию добавлены в этот backlog
  отдельными карточками.
- **Детали/ссылки:** `docs/functionality-registry.md` §7.1 (правила
  группировки пометок), `server/src/llm/review.ts`.

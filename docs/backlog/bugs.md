## B-3. Словарный запас: реестр не наполняется после чтения, оценка объёма обрезана топ-5000
- **Приоритет:** P1
- **Зависимость:** реализуется поверх F-3 (PR #27, ветка
  `feat/f-3-known-words`) — карточку брать в работу после его влития.
- **Проблема/мотивация:** Владелец прочитал первую статью после деплоя F-3 —
  экран «Словарный запас» остался полностью нулевым, и это выглядит как
  сломанная фича. Разбор показал пять причин (первые три — про наполнение,
  последние две — про оценку объёма):
  1. **Накопление невидимо.** Слово из чтения признаётся известным только после
     `READING_KNOWN_THRESHOLD = 3` встреч; до порога строки с
     `known_since = NULL` не показываются нигде (ни в сумме, ни в «Из чтения»,
     ни в списке). После первой статьи нули — «по дизайну», но пользователь не
     видит, что под капотом уже копятся десятки слов.
  2. **Статьи, сгенерированные до деплоя, не имеют лемм.** `articles.lemmas`
     заполняется LLM при генерации (default `"[]"`); чтение пре-деплойной
     (в т.ч. префетчнутой) статьи не инкрементит вообще ничего.
  3. **Молчаливые пропуски.** Если модель не вернула поле `lemmas`, схема тихо
     превращает его в `[]` — без лога и ретрая статья навсегда «пустая» для
     реестра.
  4. **Экстраполяция общего запаса из карточки F-3 не реализована.** Покрытие
     показывается только по 5 полосам топ-5000 — у читателя уровня B2/C1 запас
     заведомо больше, а экран это никак не отражает.
  5. **Систематический недосчёт полос покрытия.** Частотный список содержит
     служебные/короткие слова («te», «ya», «más», «bien», «ir»…), которые
     фильтр `normalizeArticleLemmas` (стоп-лист + мин. длина 3) принципиально
     не пропускает в реестр — даже идеальный пользователь не наберёт
     1000/1000 в первой полосе.
- **Что сделать:**
  1. Экран «Словарный запас»: показать накопление — блок «На подходе»
     (слова с `known_since = NULL` и `encounters >= 1`, с разбивкой 1/3 и
     2/3 встречи или просто счётчиком); после первого чтения экран не должен
     выглядеть пустым.
  2. Ленивая долемматизация (согласовано с владельцем): при завершении чтения
     статьи с пустым `lemmas` — один дешёвый LLM-вызов, извлекающий леммы из
     тела статьи; результат прогоняется через `normalizeArticleLemmas`,
     сохраняется на строку статьи и используется в том же завершении. Покрывает
     и старые префетчи, и молчаливые пропуски writer'а.
  3. Логировать случай «финальная статья сохранена с пустым набором лемм»
     (метрика/warning), чтобы деградация не была молчаливой.
  4. Частотный список v2 (согласовано с владельцем): расширить до топ-10 000 из
     того же источника (doozan/spanish_data, зафиксировать SHA и версию
     `SPANISH_FREQUENCY_VERSION = 2`); из списка исключить служебные слова и
     леммы короче 3 символов (согласовать состав фильтра с уже существующим
     `SPANISH_FUNCTION_WORDS`), чтобы каждая полоса была достижима; полосы
     по 1000.
  5. Экстраполяция: оценка общего запаса за пределами списка по убыванию доли
     известных с рангом (аппроксимация кривой покрытия полос, ципфовское
     затухание); на экране строка «Оценка общего запаса: ~N слов». Формулу —
     константами с обоснованием в реестре функционала.
- **Критерии приёмки:**
  - После одного завершённого чтения свежесгенерированной статьи экран
    показывает ненулевое число накапливающихся слов.
  - Завершение чтения статьи с пустым `lemmas` (пре-деплойной) долемматизирует
    её и инкрементит счётчики; повторного LLM-вызова при следующем открытии
    той же статьи нет (леммы сохранены).
  - Полосы покрытия считаются по списку v2 без служебных слов; смена версии
    списка не ломает уже накопленный реестр (сопоставление по леммам, версия
    отражена в ответе `/known-words/stats`).
  - На экране отображается экстраполированная оценка общего запаса; при пустом
    реестре — без деления на ноль и без «~0 слов» рядом с ненулевыми полосами.
  - Всё локализовано (ru/en/es); `npm run typecheck` и `npm test` в `server/`
    проходят; тесты на долемматизацию, фильтрацию списка v2 и функцию
    экстраполяции; `docs/functionality-registry.md` обновлён (§6.3, §8.3,
    раздел про словарный запас).

## B-2. Анти-фарм SRS считается по UTC-суткам, а не по локальным
- **Приоритет:** P2
- **Проблема/мотивация:** `creditAllowedToday`/`isSameUtcDay`
  (`server/src/domain/srs.ts`) сравнивают календарные сутки в UTC. Для
  пользователя в UTC+3 два «кредита» (подъёма по лестнице) возможны в одни
  локальные сутки: например, в 02:00 и в 23:00 по местному времени.
- **Что сделать:** Перевести проверку на таймзону пользователя
  (`user.timezone`, хелперы в `server/src/lib/timezone.ts`); прокинуть tz в
  `applyPracticeAnswer` и `applyReviewToBank`. Детальная постановка — этап 10.1
  роадмапа.
- **Критерии приёмки:** Два успеха в одни локальные сутки дают один подъём;
  тесты с таймзонами UTC+3 и UTC−8; известное ограничение убрано из
  `docs/functionality-registry.md` §8.2 и §24.
- **Детали/ссылки:** `docs/retention-roadmap.md` этап 10.1,
  `docs/functionality-registry.md` §8.2.
